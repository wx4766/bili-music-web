## 二、交叉共识（被 2 个以上视角独立点名 = 真问题）

| # | 共识问题 | 命中视角 | 为什么它是真的 |
| --- | --- | --- | --- |
| 1 | **HTTP 无 TLS，连锁失效** | iOS · 安全 · 开源 | 一条根因同时导致：SW 注册不了（PWA/离线全废）、cookie 不能加 `Secure`、口令明文过公网、iOS 锁屏 artwork 取图受限 |
| 2 | **口令写在 URL 且明文落盘** | 后端 · 安全 | `accessLog` 记 `req.url` 含 `?k=`，口令永久躺在 `DATA_DIR/logs/req-*.log` |
| 3 | **Google Fonts 阻塞首屏** | iOS · UX · 开源 | 国内网络要等 DNS+TLS 超时才渲染，直接拖慢「打开就能听」 |
| 4 | **收藏/历史数据是单点裸奔** | 后端 · 开源 | 只有一个 `playlists.json`，无导出、无快照；还叠加双实例并发写 |
| 5 | **远程弱网起播慢** | iOS · 后端 | 192KB 分片 × 35MB 音频 ≈ 180 次串行 RTT；限流桶被打满后客户端重试即整段报废 |

## 三、⚠️ 一处专家分歧（直接影响你的选择）

**iOS 专家建议：用 `cloudflared tunnel` 一步拿到 HTTPS。**  
**开源专家建议：前面挂 Caddy / nginx 反代。**

**裁决：自托管场景应选 Caddy，不要选 cloudflared。**  
理由：cloudflared 是**出站长连接 + 云端中转**，等于把刚甩掉的「厂商中转带宽」又请回来——
家宽上行实测 14~28 Mbps，直连的价值恰恰是不走中转。Caddy 跑在自己的机器上、自己签证书，
流量仍走已配好的路由器端口映射直连，**速度与现在一样，只是加了层 TLS**。

> 代价：自签证书 Safari 会警告一次（点「继续」即可）；若想要绿锁，
> 可用 Caddy 的 DNS-01 挑战给自己的域名签正式证书（需要对应 DNS 服务商的 API）。

## 四、合并后的优先级清单

### P0 · 影响日常使用 / 影响开源信誉（6 项）

| # | 问题 | 来源 | 具体后果 | 状态 |
| --- | --- | --- | --- | --- |
| 1 | **双实例共享 DATA_DIR 无跨进程锁**，`.tmp` 固定名 | 后端 | 两个实例同时写 history/playlists，「读-改-写」撞车即丢收藏、续播位置回退 | ✅ v1.1.0 已修 |
| 2 | **口令明文进日志 + `/api/log` 路径穿越** | 安全 + 后端 | 任何人拿到日志＝拿到永久口令；`?f=../../app/server.js` 可任意文件读 | ✅ v1.1.0 已修 |
| 3 | **iOS 内存三重驻留** | iOS | 当前 + 上一首 + 下一首预取 + 合并时全量复制 ≈ 120~140MB，逼近 iPhone 单页上限 | ⬜ 第二波 |
| 4 | **分片 192KB 导致往返爆炸** | iOS + 后端 | 35MB 音频约 180 次串行 RTT；触发 429 后整首报废 | ⬜ 第二波 |
| 5 | **Docker 镜像没有 ffmpeg** | 开源 | 「iOS DASH 重混」在**推荐部署路径**上静默失效，外部 iOS 用户只能听 20 秒且无报错 | ✅ v1.1.0 已修 |
| 6 | **README 缺前置条件与验证步骤** | 开源 | 陌生人 5 分钟跑不起来，失败了也不知道卡在哪 | ✅ v1.1.0 已补 |

### P1 · 体验跃迁（11 项，按性价比排序）

1. ⬜ **上 HTTPS（Caddy 反代）** —— 一条改动同时解锁 PWA 离线、cookie `Secure`、口令不再明文、锁屏封面
2. ⬜ **口令改造**：一次性表单 POST 或 `Authorization` 头换取 cookie；`timingSafeEqual`；cookie 补 `HttpOnly`
3. ✅ **Google Fonts 本地化** —— v1.1.0 已改为系统字体栈（`-apple-system` / `PingFang SC` / `ui-monospace`），零外部请求
4. ⬜ **Media Session 补 `seekto` / `seekbackward` / `seekforward`**；`nexttrack/previoustrack` 改走 `advance()`
5. ⬜ **收藏夹导出 / 导入 + 每日快照保留 7 份**
6. ⬜ **热区 ≥44px + 放开双指缩放 + px 改 rem**
7. ✅ **仓库瘦身 + 版本号统一** —— v1.1.0 已移除 `design-demos/`（约占仓库 40% 体积），版本统一为 1.1.0
8. ⬜ **缓存落盘加独占临时名 + 内容校验**（现在只判 `size>=64KB`，半截文件会污染缓存）
9. ⬜ **无 Range 的响应也要分片**
10. ⬜ **缓冲/失败状态可见**（迷你条加缓冲态；toast 层级提到弹层之上）
11. ⬜ **播放控制提级**（播放模式/睡眠定时藏在歌词面板两级深处）

### P2 · 长期打磨（节选）

- 睡眠定时改「存 `sleepEndAt` + 回前台补偿」，当前靠 `setInterval`，锁屏即失效
- 随机算法换 Fisher-Yates 洗牌袋（现在会连续重复同一首）
- 长列表虚拟化 / 分页增量渲染
- `ACCESS_TOKEN` 未设置时拒绝启动（现在 fail-open，忘配即裸奔）
- 限流键不再无条件信任 `X-Forwarded-For`（改头即绕过）
- Dockerfile 加 `USER node`、镜像标签钉版本
- 进度条拖动与 `timeupdate` 回写打架，改为「拖动中不跟随、松手才 seek」
- 补 `CONTRIBUTING.md` / issue 模板 / CI（语法检查 + docker build）

## 六、一句话结论

**当前最值得做的不是加新功能，而是三件事**：堵住「双实例写丢数据」和「口令落日志」这两个真实在跑的洞（v1.1.0 已完成），
然后用一层 Caddy 把 HTTPS 加上面——这一条会连锁解锁 PWA、离线、锁屏封面和口令安全。  
功能层面的头号机会是**收藏夹导出备份**（现在的数据只有一个 JSON 文件，且可能有两个进程在写它）。
