# bili-music-web UI 重设计 · 设计 Spec（三方向共同输入）

## 产品是什么
「B站音乐 · 随身听」：跑在家庭 NAS 上的 B 站音乐播放器，以 iOS PWA（添加到主屏幕）形态使用。
用户在手机上搜 B 站音频投稿 → 播放 → 看歌词 → 收藏。技术上是单页 Web 应用，会以全屏
standalone 模式运行，视觉上必须像原生 iOS App，而不是网页。

## 目标用户与场景
- 老汪（成都，家里两女儿），日常通勤/散步/做家务时用手机听歌。
- 场景特征：单手操作、户外光线（列表文字要清楚）、锁屏/后台播放为主界面停留时间短。
- 情感基调：听音乐的放松感 + 一点点极客自豪感（这是自己 NAS 上的私人服务）。

## 必须覆盖的界面状态（一个 HTML 内呈现）
1. **主视图（搜索/列表）**：顶部品牌区 + 搜索框 + 结果列表（真实数据见 mockdata.json，
   6 条，含封面图 URL、标题、UP 主、时长、播放数）。当前正在播放的条目要有"正在播"状态。
2. **底部迷你播放条**：封面缩略图 + 歌名 + UP 主 + 进度 + 播放/切歌按钮，固定底部。
3. **歌词全屏面板**：点击迷你条展开 → 大封面/大歌名 + 滚动歌词（含高亮当前行）+ 大控制区
   （进度条 + 上一首/播放/下一首 + 收藏）。提供可点击的展开/收起交互。

## 真实内容（不用 Lorem）
读 `mockdata.json`：6 首真实搜索结果（标题/作者/封面 pic URL/时长/播放数）。
当前播放固定为第 1 条《晴天》。封面图直接用真实 URL，
页面必须带 `<meta name="viewport">` 与 `<meta name="referrer" content="no-referrer">`
（B 站图床防盗链需要）。

## 硬约束
- 输出：**单文件 HTML**（内联 CSS/JS，可用 Google Fonts CDN），移动视口 390×844 设计基准，
  允许页面纵向滚动。
- 正文可读性底线：正文 ≥14px、辅助文字 ≥12px、对比度 ≥4.5:1。
- 禁 AI slop：不搞紫渐变、不每个标题配 emoji 图标、不搞圆角卡片+左彩条组合。
- B 站身份基因要保留：粉 #FB7299 与蓝 #23ADE5 至少一个作为 accent 出现（怎么用由方向定）。
- 触控目标 ≥44px；底部播放条要考虑 iPhone 底部安全区（示意即可）。
- 深色底优先（夜间听歌场景），但允许某方向用浅色系给出对比。
- 歌词面板、列表、迷你条三个状态**骨架结构要清晰**，不要为了风格牺牲信息层级。

## 视觉母题线索（从内容里长出来的素材）
- 这是从 B 站"抠"音频来的播放器 → 视频网站基因：弹幕、播放数、时长徽标、UP 主。
- 私人 NAS 服务 → "我的音乐馆/随身听"的专属感，不是公共平台。
- 封面图永远是主角（正方形、低解析度缩略图放大有颗粒感——可以把"颗粒/像素"变成母题）。
